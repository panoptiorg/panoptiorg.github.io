How panopticode works

Two kinds of programs. A frontend knows one language and its libraries: it reads one repository and writes down facts about its code. The engine knows no language at all: it reads the facts of all your repositories at once and finds the routes untrusted data can take to a dangerous call.

Part 1 · the frontends

Code becomes facts.

One frontend per language. Each one knows its language and the libraries that move data between services, such as gRPC, GraphQL, HTTP, Kafka and SvelteKit. It writes down what the code does. The only security fact it records is the one only it can see: which parameters receive requests, such as a handler's input or a resolver's arguments. Every other rule, what counts as a source, a sink or a sanitizer, comes from the catalog, which only the engine reads (step 06).

Part 2 · the engine

Facts become summaries.

The engine is one Rust program. It loads the facts of any number of repositories and one policy file, and works out what every function does with untrusted data.

Summaries become routes.

A summary says that data gets through, not how. The last steps rebuild the how, hop by hop, and can check it a second time from the other end.
